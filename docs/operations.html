Operations

Select an image workflow

Choose the matching file in .github/workflows/ and read its workflow_dispatch.inputs before dispatch. The repository includes Ploinky Node, Ploinky Box, OnlyOffice, Umami, local LLM, SearchAgent, OpenCode Free, RoboTeam, LiveKit, Soul Gateway, and Bubblewrap image definitions. The QA Git workflow produces a toolchain archive rather than an agent image.

Ploinky Box

publish-ploinky-box-image.yml requires a full Ploinky commit SHA. It resolves AchillesAgentLib and MCP SDK selections once, then gives both native builds those exact library commits. Each native build records proof for its immutable image. The candidate index is assembled from proven native manifests. promote_stable defaults to false.

promote-ploinky-box-candidate.yml validates the candidate's original publication inputs, saved proofs, immutable registry data, and acceptance receipt before moving stable aliases. The v2 receipt binds the revisions, taken from the frozen source inventory that each cohort's preflight and postflight repeat, and six required gates to the Box generations observed in their preflight evidence (three cohorts, each within 30 minutes of its Box start); operators must retain the underlying reports, preflights, and postflights because receipt validation alone does not prove a browser test ran.

Other image contracts

Umami publication checks its pinned source, compiled Router base path, local ingress, and native runtime evidence. OnlyOffice, LiveKit, and patched Egress publication build and prove each architecture on its own native runner, assemble only the proven layouts into one index, and verify its digest and platform set before registry mutation; OnlyOffice requires a pre-approved index digest. LiveKit also accepts only an exact source revision and an Egress index with exactly the amd64 and arm64 platforms. These workflows have distinct inputs; parameters from one workflow are not interchangeable with another.

Bizanso runtime

The Bizanso image provides dependencies and a pinned local model without copying the private application. Its native amd64 and arm64 gates exercise offline inference, SQLite, and document commands. Both successful proofs are required before candidate assembly; explicit promotion controls the stable tag. The private consumer adopts the verified digest separately and mounts its source read-only outside the image's dependency and model directories.

Credentials and tests

Publishing workflows use named GitHub secrets such as DOCKERHUB_TOKEN; private source checkouts can require SOURCE_REPO_TOKEN. Keep values outside the repository. tests/*.test.mjs contains Node test modules covering image definitions, proof validation, promotion, and runtime helper contracts. Inspect a selected test's side effects and fixtures before running it. Building, publishing, promoting, and changing consumer image pins are separate operations.
