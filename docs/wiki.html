Wiki

These terms describe the project's own components and contracts.

Candidate

A candidate is a built image or multiarchitecture index addressed by immutable digest and associated with the workflow run that produced it. A candidate can be inspected and accepted before a stable tag is moved. The applicable workflow determines which native proofs and source revisions the candidate must retain.

Promotion

Promotion moves a stable registry alias to an accepted candidate. It is a registry change separate from compilation and from updating a consumer manifest. The Box promotion workflow validates the candidate publication context and acceptance receipt before writing its aliases and confirms the resulting indexes afterwards.

Acceptance receipt

The Ploinky Box receipt is a bounded canonical JSON document describing the selected image, revisions, and required acceptance phases. Validation checks schema, identities, counts, and report hashes. The receipt is an operator attestation tied to retained evidence; it cannot independently prove that the referenced browser runs occurred.
