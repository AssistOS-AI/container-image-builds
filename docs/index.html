Image ownership

The repository owns Dockerfiles under images/ and publishing workflows under .github/workflows/. Agent source may come from a separately selected repository revision. Pinned checkout material beneath sources/ is build input, not a second place to edit the source.

Candidate publication and promotion

Workflows that separate publication from promotion first publish and verify a candidate. Their explicit promotion input controls movement of stable aliases. Ploinky Box also has a separate promotion workflow for an already built candidate, with retained proof and an acceptance receipt.

Verification boundaries

Native image builds and workflow-specific smoke checks establish different claims from repository tests. A valid Dockerfile or passing static test does not establish that a published image passed runtime acceptance. Each image's workflow defines its exact source inputs, architectures, credentials, and proof requirements.

Coding style defines source layout and the verification commands. Wiki contains the canonical project terms.
